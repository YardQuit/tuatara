#+title: Tuatara
#+subtitle: An editor in Common Lisp, after the ideas of Emacs

Read the manual: [[https://tuatara-editor.github.io/tuatara/][tuatara-editor.github.io/tuatara]].

* What Tuatara is

An editor built on Emacs's design: a small core with everything else built on
it, buffers as the universal container, every key bound to a named command, and
nothing off limits to the person using it. Unlike Emacs, whose core is written
in C, Tuatara is Lisp throughout, the core included.

It is *not* compatible with Emacs Lisp or Emacs packages. It keeps the ideas,
not the code. In exchange it gets real parallel threads, a text model that
handles files of many gigabytes and half a million cursors, and one language
from the rope up to the init file.

- Language :: Common Lisp, compiled by SBCL.
- Platform :: Linux. A window of its own (GTK 4), or any terminal (ncurses).
- Editing :: DONKEY modal editing on by default, on top of the standard
  Emacs-style keys; =(setf *modal-editing* nil)= turns the modal layer off.

* What it does

- Files of any size: memory-mapped and indexed on nine cores in ten, nothing
  read up front; any encoding and line ending; a hex view; a safe way to open
  a file that must stay untouched (=M-x find-file-safely=).
- Editing: undo groups, rectangles, multiple cursors, selections by the syntax,
  input methods and digraphs, spell checking, sorting, filling, bracket pairs.
- Searching: incremental search with regular expressions, replacing, search
  across many files as you type, an outline of the buffer.
- Languages: colouring, indentation and selections by tree-sitter for close to
  300 languages, and Lisp in the running editor (completion, =M-.=, a REPL,
  macro expansion, a debugger).
- Org: the Org format read as Org itself reads it, folding, tables and their
  formulas, the agenda, capture, clocking, links, tangling, dynamic blocks,
  and export to PDF (through LaTeX) and to Word.
- Files with formatted names, a journal and a calendar.
- rimu, a directory editor, with the trash, a preview, and git status.
- Viewers for PDFs, pictures, and Word, Excel and PowerPoint documents and
  LibreOffice's own (OpenDocument, .odt, .ods, .odp), each drawn by a program
  shut in a sandbox (bubblewrap), the Office ones also read as text by
  Tuatara itself: nothing in a file is ever run.
- Auto-save into a private directory of its own, never into the file itself
  (only a save writes that); =M-x recover-file= takes the changes back after a
  crash or a quit without saving (=M-x list-auto-saves= lists them all).
  Nothing opened safely is ever copied.
- Encrypted files (.gpg) opened decrypted and saved encrypted by GnuPG, their
  text never written to disk (no auto-save, scratch file or clipboard but on
  request); a file opened safely is never decrypted.
- The session kept, as an option (=*keep-session*=): the files, directories and
  windows opened again as they were at the next start.
- =M-x show-file-metadata= shows what a file is and says of itself, read by
  Tuatara alone (no other program): kind by contents, owner, permissions, its
  four times, SHA-256, extended attributes (where a download came from); a
  photograph's EXIF with its GPS position and thumbnail (JPEG, HEIC, PNG, WebP,
  TIFF), XMP and its edit history, a PDF's information, saves and scripts, MP3
  and FLAC tags, a video's times and place, an Office file's account of itself.
- A terminal in a buffer (=M-x terminal=, on the terminal library of Ghostty),
  with its history as text, the mouse, links and pictures.
- Help over the live editor: every command, variable and face has its
  documentation, and the source of anything is one key away.

* Running it

** Installing it, step by step

1. *Download.* Open the releases page,
   [[https://github.com/Tuatara-Editor/tuatara/releases]], and under the newest
   release's /Assets/ download the file for your system (the table below) and
   =SHA256SUMS=, into your Downloads directory.

2. *Check the download.* In a terminal:

   #+begin_example
   cd ~/Downloads
   sha256sum -c --ignore-missing SHA256SUMS
   #+end_example

   It must say =OK= after your file. If it says =FAILED=, download it again.

3. *Install it* with your system's own package manager, which also brings
   the libraries Tuatara needs:

   | System                                  | Download                      | Install                                       |
   |-----------------------------------------+-------------------------------+-----------------------------------------------|
   | Fedora 40 and newer                     | =tuatara-….x86_64.rpm=        | =sudo dnf install ./tuatara-*.x86_64.rpm=     |
   | Ubuntu 24.04 and newer, Debian 13       | =tuatara_…_amd64.deb=         | =sudo apt install ./tuatara_*_amd64.deb=      |
   | Arch                                    | =tuatara-…-x86_64.pkg.tar.zst= | =sudo pacman -U tuatara-*-x86_64.pkg.tar.zst= |
   | Omarchy                                 | =tuatara-…-x86_64.pkg.tar.zst= | =sudo pacman -U tuatara-*-x86_64.pkg.tar.zst= |
   | Anything else, or nothing installed     | =Tuatara-x86_64.AppImage=     | see /The AppImage/ below                      |

4. *Start it.* In a terminal, =tuatara= runs it in that terminal and
   =tuatara --gui= in a window of its own; it is also among your desktop's
   applications, as /Tuatara/.

   =tuatara +120:8 main.lisp= opens the file with the cursor on line 120, column
   8 (columns count from 1, while the =C= of the mode line counts from 0; the
   line alone, =+120=, is enough; a file with fewer lines opens at its last, and
   that is said); each file may have its own, as in =tuatara +3 a.txt +40
   b.txt=. =tuatara --diff OLD NEW= shows what differs between two files, or two
   directories, and ends when you quit it; for git, run =git config --global
   difftool.tuatara.cmd 'tuatara --diff "$LOCAL" "$REMOTE"'= once, then =git
   difftool --tool=tuatara=.

   =tuatara --merge LOCAL BASE REMOTE MERGED= merges the three into MERGED,
   the conflicts marked there to resolve (=C-c ^ n= goes to the next, =C-c ^ u=
   and =C-c ^ l= keep a side), then save; it ends with 0 when MERGED is saved
   with no conflict left, else 1, so that git can trust it: =git config
   --global mergetool.tuatara.cmd 'tuatara --merge "$LOCAL" "$BASE" "$REMOTE"
   "$MERGED"'= and =git config --global mergetool.tuatara.trustExitCode true=,
   then =git mergetool --tool=tuatara=.

   =tuatara --safe FILE= (or =-R=) opens files safely, read only and acted on by
   nothing, as the files of an evidence directory open; =tuatara --hex FILE=
   opens them in the hex view; =... | tuatara -= reads standard input into a
   buffer opened safely, the terminal staying the keyboard; =tuatara --tutor=
   starts in the tutor; =tuatara -Q= (=--no-init=) starts without the init file
   and packages, what Tuatara keeps between sessions kept apart for that session
   and the real one neither read nor changed. After =--= every argument is a
   file's name. Options may stand anywhere before =--=, =--safe= and =--hex=
   holding for every file of the call. =tuatara --help= lists the rest.

5. *First steps.* =M-x tuatara-tutor= teaches the keys by editing a text with
   them (=M-x= is Alt and x). =M-x check-health= says which of the programs
   in /What to install beside it/ are found. Your settings are in
   =~/.config/tuatara/init.lisp=, written the first time Tuatara starts, every
   setting in it explained and switched off (=;;= in front).

To remove it again: =sudo dnf remove tuatara=, =sudo apt remove tuatara= or
=sudo pacman -R tuatara=.

*** On Omarchy

Omarchy is Arch underneath, so Arch's package installs Tuatara as it is:

#+begin_example
cd ~/Downloads
sha256sum -c --ignore-missing SHA256SUMS
sudo pacman -U tuatara-*-x86_64.pkg.tar.zst
#+end_example

Then open the app launcher (=Super= + =Space=) and type /Tuatara/, or run
=tuatara= in a terminal. The programs it uses beside it are Arch's too (see
/What to install beside it/). To see pictures and PDF pages inside a
terminal, use a terminal with the kitty graphics protocol, kitty or Ghostty
(=sudo pacman -S kitty= or =sudo pacman -S ghostty=); in its own window
(=tuatara --gui=) they are always shown. Using the AppImage instead, Omarchy
needs FUSE 2 for it first: =sudo pacman -S fuse2=.

** The AppImage

One file, nothing installed, for a system the packages above do not cover;
it runs on Linux with glibc 2.39 or later (Ubuntu 24.04, Debian 13, Fedora
40 and newer). On Arch and Omarchy, install FUSE 2 first
(=sudo pacman -S fuse2=).

#+begin_example
chmod +x Tuatara-x86_64.AppImage
./Tuatara-x86_64.AppImage FILE          # in this terminal
./Tuatara-x86_64.AppImage --gui FILE    # in a window of its own
./Tuatara-x86_64.AppImage +120 FILE     # with the cursor on line 120
./Tuatara-x86_64.AppImage --diff OLD NEW
./Tuatara-x86_64.AppImage --install-desktop
#+end_example

=--install-desktop= copies it to =~/.local/bin/tuatara= and puts Tuatara in
the desktop's applications, with its icon and in "Open With" for text files,
and beside it "Tuatara (client)", which opens the files in a window of the
daemon (=tuatara --daemon=), or of an editor of its own when none runs;
=tuatara --remove-desktop= takes them away again. =tuatara
--generate-autostart= has the desktop start the daemon as you log in; nothing
starts it unless you do.

The window's title bar is in GTK's light style unless asked otherwise: =--dark=
before the rest shows it dark (=./Tuatara-x86_64.AppImage --dark --gui FILE=),
and =--install-desktop --dark= starts it so from the desktop's applications.
Programs started from Tuatara are shown dark too. The editor's own colours are
its theme's (M-x load-theme).

Installed from a package instead, Tuatara is in =/usr/lib/tuatara/= and uses
the system's own GTK and libraries; the AppImage's =--dark= and =--light= are
not there, and =GTK_THEME=Adwaita:dark tuatara --gui= does what =--dark= does.

The libraries the AppImage brings (GTK 4 and what it needs) are Ubuntu 24.04's
at their newest versions on the day it was built. Each release has
=Tuatara-x86_64.AppImage.libraries.txt=, also inside the AppImage as
=licenses/bundled-libraries.txt=: every bundled library with its package, exact
version and SHA-256, so it can be checked against security advisories. The
libraries come with their sources, as many of their licences (the LGPL among
them) ask: =Tuatara-x86_64.AppImage.library-sources.tar.zst=, a file of the
same release, holds the Ubuntu source package of each, at exactly the version
bundled.

** Building the files yourself

=tools/appimage.sh= makes the AppImage, and =tools/distro-packages.sh= the
packages for Fedora (40 and newer), Ubuntu (24.04 and newer) and Arch, in
=build/packages/=.

Tuatara works on any file system, and best on one that shares blocks between
files: btrfs, XFS, bcachefs or ZFS. There a copy it keeps of a large file
another program changes, and the scratch files of work on a large buffer, take
no time and no space, and a save shares the blocks of what did not change
wherever it can. Elsewhere they are whole copies, kept in Tuatara's cache
directory when it has room.

To build it from source, and to work on it, see
[[file:HACKING.org][HACKING.org]]; to contribute,
[[file:CONTRIBUTING.md][CONTRIBUTING.md]].

** What to install beside it

Tuatara edits text with nothing else installed. Some features use programs of
the system, each for one thing; without one, that thing is only not there, and
=M-x check-health= says what is found and what is missing.

In the window and in a terminal alike:

| Program                        | What it gives                                                        |
|--------------------------------+----------------------------------------------------------------------|
| bubblewrap                     | the sandbox every program reading a file for Tuatara runs in: without it no PDF, picture or Office document is shown |
| poppler's tools                | PDFs as pages, their text and attachments                            |
| ImageMagick                    | pictures of every kind, and their previews                           |
| bsdtar (libarchive)            | zip, 7z, rar, ISO 9660 and cpio archives listed and extracted in rimu |
| 7-Zip (7zz)                    | the best of archives: encrypted 7z and rar, more zip methods; used before bsdtar |
| LibreOffice (Writer, Calc, Impress) | Word, Excel, PowerPoint and OpenDocument files shown as pages    |
| enchant and a hunspell dictionary | spelling                                                          |
| git                            | the git status (=C-x g=), and packages fetched                       |
| GnuPG                          | =.gpg= files opened and saved encrypted                              |
| OpenSSH and util-linux's setpriv | a daemon on another machine shown here (=--client=HOST:=), your ssh agent lent to it for each use you confirm; files on a server (=/ssh:HOST:/path=) |
| xdg-utils                      | a file opened in the desktop's own program, a link in the browser    |
| XeLaTeX or LuaLaTeX            | Org documents exported to PDF                                        |
| a language's server and formatter | completion, errors and layout for that language; =M-x check-health= names the one each language looks for |

In the window, Tuatara takes the desktop's monospaced font (=*gui-font*= sets
another); one with ligatures shows them. In a terminal, more is up to the
terminal:

- 24-bit colour, which kitty, Ghostty, WezTerm, foot, Konsole and GNOME's
  terminal have, for the theme's own colours;
- the kitty keyboard protocol (kitty, Ghostty, WezTerm, foot), so that
  Escape, Alt and Control keys arrive at once and whole;
- the kitty graphics protocol (kitty, Ghostty), for pictures and PDF pages
  shown in the terminal, not inside tmux or screen;
- wl-clipboard on Wayland, or xclip or xsel on X11, to copy and paste with
  other programs;
- a Nerd Font, only for the signs the init file can give the mode line.

To install them all:

#+begin_example
# Fedora
sudo dnf install bubblewrap poppler-utils ImageMagick bsdtar 7zip libreoffice-writer libreoffice-calc \
  libreoffice-impress enchant2 hunspell-en git gnupg2 xdg-utils wl-clipboard xclip \

  'tex(fancyhdr.sty)' 'tex(float.sty)' 'tex(fontspec.sty)' 'tex(fvextra.sty)' 'tex(geometry.sty)' \
  'tex(graphicx.sty)' 'tex(hyperref.sty)' 'tex(lastpage.sty)' 'tex(longtable.sty)' \
  'tex(multicol.sty)' 'tex(rotating.sty)' 'tex(titlesec.sty)' 'tex(ulem.sty)' 'tex(wrapfig.sty)' \
  'tex(xcolor.sty)' 'tex(xltabular.sty)'
# Ubuntu
sudo apt install bubblewrap poppler-utils imagemagick libarchive-tools 7zip libreoffice-writer libreoffice-calc \
  libreoffice-impress libenchant-2-2 hunspell-en-us git gnupg xdg-utils wl-clipboard xclip \
  texlive-xetex texlive-latex-extra texlive-plain-generic
# Arch and Omarchy
sudo pacman -S bubblewrap poppler imagemagick libarchive 7zip libreoffice-fresh enchant hunspell-en_us git \
  gnupg xdg-utils wl-clipboard xclip texlive-xetex texlive-latexextra texlive-plaingeneric
#+end_example

The LaTeX lines give the export every LaTeX package it uses; a whole TeX Live
from tug.org does too, found in =~/.texlive/=, =~/texlive/=,
=/usr/local/texlive/= or =/opt/texlive/= with nothing set.

* Configuration

=~/.config/tuatara/init.lisp= (=XDG_CONFIG_HOME= respected) is loaded after the
defaults, in the =tuatara-user= package. The first start writes one that lists
every setting, commented out. For example:

#+begin_example
(bind-key "C-c t" 'end-of-buffer)                ; in every modal state
(bind-key "SPC ." 'beginning-of-buffer :map :normal)
(bind-key "; ;" 'end-of-line :map :leader)       ; under SPC and C-x SPC
(unbind-key "C-x C-b")
(set-face :comment :fg :cyan :italic nil)        ; faces: see lisp/theme.lisp
(load-theme 'ao-light)                           ; ao-dark (the default), terminal, plain
(setf *escape-quits* t)                          ; Escape does what C-g does
#+end_example

Everything the defaults do is ordinary Lisp in =lisp/=; the init file can
redefine any of it.

* Status

Version 0.90.30, a pre-release: in daily use by its author, its parts tested
(=tools/test.sh=, about 225,000 checks), its interfaces still changing until
1.0.0, the first stable release.

From 1.0.0 on, the version says what changed, as semantic versioning has it.
What packages and init files are written against (the package API, the
settings of the init file and the names of the commands) changes in a way
that breaks them only in a new major version (2.0.0), and only after a
release before it has marked the name obsolete; a minor version (1.1.0) adds,
a patch (1.0.1) fixes.
